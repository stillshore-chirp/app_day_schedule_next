# Accessibility Checklist

- [ ] Critical flow can be completed with keyboard only.
- [ ] Schedule move / resize has non-drag equivalent.
- [ ] Focus is always visible and not obscured by current-time line / overlays.
- [ ] Focus order is natural and focus restores after modal / permission.
- [ ] No keyboard trap.
- [ ] Controls have accessible name matching visible label.
- [ ] Icon-only controls have meaningful names; destructive action has visible text.
- [ ] Schedule blocks expose title, time range, selection and relevant state.
- [ ] Regions / headings / list / grid semantics are meaningful.
- [ ] Error is associated with input and explains correction.
- [ ] Save / sync / conflict / permission status is announced at appropriate granularity.
- [ ] Every-second clock / countdown is not over-announced.
- [ ] Color is not the only carrier of category / conflict / sync / current state.
- [ ] Text and non-text contrast are sufficient.
- [ ] Target and resize handles are large enough.
- [ ] 200% text / high DPI / narrow window remains operable.
- [ ] Reduced motion / sound alternatives are considered.
- [ ] Automated and manual results are both reported.
